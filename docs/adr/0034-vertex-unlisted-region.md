# ADR-0034: A Vertex AI deployment is never priced by a region-less entry

**Status:** Accepted (amends [ADR-0028](0028-price-coverage-and-regional-prices.md), point 3)
**Date:** 2026-11-27

## Context

ADR-0028 lets a catalog entry be scoped to Regions (`regions`). For a deployment whose Region no
entry of the id lists, lookup falls back to the entries without `regions`, and `check-config` and
`serve` only warn. That fallback is right where the region-less entry is the provider's price for
"everywhere else" (Azure OpenAI, Bedrock).

It is wrong for Google. The bundled catalog keeps the Gemini API prices as the region-less
`google/*` entries, and the Vertex AI prices, generated by `scripts/vertex_prices.py`, as
Region-scoped entries under the same ids. The Gemini API and Vertex AI are different products with
different prices. A Vertex deployment (the `google` adapter with `auth: bearer_token`) in a Region
the entries do not list, for example `us-central1` or `europe-west4` for `gemini-4-carbon`, was held
and booked at the Gemini API price: 4.00 / 20.00 USD per million tokens where Vertex bills 4.40 /
22.00, about 10% low on every call. A security review found it (SG-PT-08); one start-up warning was
the only sign. A Vertex deployment of an id that has only Gemini API entries got the Gemini API
price with no warning at all.

The Cloud Billing API splits Vertex prices into global and non-global SKUs only, so the non-global
price probably applies to every non-global Region. But the importer writes the non-global entry
with the Regions Google's locations page lists for the model, and marks it as non-global only in
its free-text `note`. Nothing machine-readable says that an entry prices every non-global Region,
and a Region missing from the locations page may also be one the model is not sold in.

## Decision

- **A route with a Vertex AI deployment is priced only by entries that list its Regions.** Lookup
  takes the Region-scoped entries that list the deployment's Region and never the region-less
  ones; with none in force, the route has no price. The rule applies to the whole route when any of
  its deployments is a Vertex one (`google` with `auth: bearer_token`); every deployment of a route
  shares one price anyway (ADR-0028, point 4).
- **Start-up refuses it.** `check-config` and `serve` exit 3 for such a route when a Vertex Region
  is priced by no entry that lists it (today, or on any date when run without a clock), naming the
  route, the Region and the Regions the id does list. This replaces the warning for these routes.
- **Calls are refused too.** A call on a route whose Vertex Region is listed only by an entry not
  yet in force gets `model_not_priced` (404), never the Gemini API price. No new error code.
- **No inferred non-global price.** We do not price an unlisted non-global Region with the id's
  non-global entry: the catalog has no field that marks an entry as covering every non-global
  Region, and inferring it from a `note` or from the Region's name would be a guess (ADR-0003). An
  operator who knows the price adds it in a `catalog.paths` file (`regions: [<Region>]`), for
  example with `spendgate catalog draft --like google/<model> --region us --as google/<model>
  --regions <Region>`.
- **Everything else keeps ADR-0028.** Other providers, and `google` with `api_key` (the Gemini API),
  still fall back to the region-less entry, with the start-up warning.

## Consequences

- A Vertex route in a Region the catalog does not list stops starting after the upgrade (exit 3),
  where it used to start with a warning and under-hold by about 10%. Move it to a listed Region
  (`global`, or the `us` / `eu` multi-region endpoints for Gemini 4 Carbon) or price the Region
  in an override file.
- A Vertex deployment of an id the importer does not generate (only Gemini API entries) is refused
  the same way.
- A future machine-readable mark on the importer's non-global entries could let lookup price every
  non-global Region with them; that would be its own decision.
- No schema, ledger or endpoint change. Library mode is unaffected: its routes without a config file
  never include Vertex.
